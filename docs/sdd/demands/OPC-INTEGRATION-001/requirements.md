# OPC 全量集成与双客户端统一接入

## 1. 背景与确认边界

产品未来面向外部客户，当前在内部员工中试点，预计用户规模为 1000 人。最紧急的问题是各产品登录与权限没有打通，员工无法通过一致身份使用办公端、代码端和云端企业资源。1000 人是用户规模，不解释为 1000 并发；部门数量、并发负载与响应时间指标尚未提供。

本需求以集成方案 v3 为来源，按用户 2026-10-20 后续决定调整范围：统一登录、权限、知识库、企业技能分发和精确 MCP 调用均为本轮必做；组织同步通过受保护接口由管理员手动触发，不建设事件驱动或定时自动同步；云端 Agent 委托移入后续待办；本轮不引入 OpenBao；发布与回滚按最小必要范围实施。登录后的企业资源使用闭环必须完整交付，不能只完成登录。外部商业化是产品方向，本轮交付和验收对象仍是内部试点。

2026-10-20，用户以“确认联合卡”确认需求身份、四仓范围与远程基线、完整 SDD（full）和 Loop 路线、分支名称、macOS/三种 CLI 验收范围、主仓治理形态及 Git 身份角色映射。此前以“好，符合我的意思”确认：保留全量目标，优先复用现有接口；确需修改 knowledge-opc 时说明必要改动和维护影响并单独确认；不以关闭能力代替完整交付。后续用户明确的范围调整优先于该历史全量决定；本轮必做项仍不得以关闭能力冒充完成。

## 3. 目标和范围

### REQ-001 统一个人身份与登录

员工在 work 和 code 中使用同一可追溯的企业身份登录，并获得该身份当前允许进入的空间。使用不可变身份来源和主体标识建立关联，不因同名或相同 email 自动合并账号；改邮箱不创建新的员工身份。存量身份冲突应拒绝自动合并并提供管理员可处理的结果。

客户端只能持有自身受限授权，不能以共享空间 endpoint token 或管理员 token 冒充员工身份。登录、退出、过期、续期、停用和重放失败均有可观察结果；原生端安全授权、一次性兑换及凭据保存方式由 Architecture/Specification 固定。

达成依据：ACC-001、ACC-002。对应 v3 §4.1、§6。

### REQ-002 空间隔离与有效权限

客户端的账号、空间、云连接、技能缓存和运行上下文必须隔离。切账号或空间后旧运行时、连接和缓存引用不得继续为新上下文服务。服务端重新授权资源 ID，不信任客户端传入的 tenant/workspace/KB/document ID。

OPC 角色不自动授予本机文件或 shell 权限。有效执行权限取云授权、受管策略和本机许可的交集；保留个人能力时不得绕过企业受管范围。服务密钥、个人 OAuth 凭据与云 stdio 配置不下发到员工电脑。

达成依据：ACC-002、ACC-005、ACC-009。对应 v3 §3、§4、§6。

### REQ-003 撤权覆盖双端与在途任务

网关应用权限变更后 60 秒内，停止受影响身份的新云调用及运行授权续租；覆盖双端会话、code HTTP/WS/PAT、Daemon 和已领取任务的后续云访问。运行授权绑定实际用户、空间、任务和设备，任务结束即回收。设备注册身份不能单独获得员工云资源权限。

敏感写操作执行前重新验证当前授权，授权服务不可达时写操作失败关闭。撤销或退出不能被刷新、重连、旧任务 token 或历史共享 endpoint token 绕过；历史共享凭据须有盘点和迁移/失效验证。

60 秒从网关应用变更起算，不冒称从统一账户中心发生变更起算。本轮依赖管理员手动触发同步：账户中心发生变更到管理员触发之间的等待不承诺自动检测时限；规格须固定手动触发到变更应用的处理时限、失败结果与重试方法，验收分别记录触发、应用和撤权时刻。未触发或同步失败不能报告已完成撤权。撤权约束后续访问，不承诺抹除先前已返回到本机的信息，不要求强制终止与云无关的合法本地工作。

达成依据：ACC-003。对应 v3 §4.1、§9、§10。

### REQ-004 个人权限下的知识检索和阅读

两端可在授权空间检索知识并获取可阅读内容。结果包含可追溯知识/片段标识、标题、引用定位与来源空间；员工能判断答案依据。检索、读取、引用跳转均遵循当前用户权限，不借服务端代理提高权限。

预览和原文件下载分别授权；Viewer 不能因为能够预览而获得原文件下载或写权限。试点使用共享 endpoint 时，凭据只留在网关或受控服务器配置中，不作为可绕过个人撤权的员工凭据。

达成依据：ACC-002、ACC-004。对应 v3 §4.2、§9。

### REQ-005 网关安全与可追溯发布

管理接口和同步触发入口具有服务内认证、权限范围检查、来源/CSRF 防护与审计；全局操作只允许系统管理员，部门管理员限定本空间。恢复 TLS 证书校验，秘密采用受控注入，日志和仓库不保存明文凭据。

保留现有组织接入能力，但对共享 JWT 签发、直接写 OPC 存储等过渡依赖明确责任和兼容性检查；个人凭据留在服务器并受逐用户生命周期管理。部署物可追溯到源码、镜像及配置版本；安全基线未通过，不开放新的公网网关入口。本轮不引入 OpenBao，优先使用经验证的现有受控密钥注入和存储方式。若后续判断必须引入，须先向用户说明现有方式不能满足的具体要求、替代方案不足和引入成本，并取得明确同意；不得由实现者自行增加该依赖。

达成依据：ACC-005、ACC-010。对应 v3 §5、§7。

### REQ-006 手动触发组织同步与反向清权

提供受 REQ-005 鉴权、权限范围和审计约束的同步接口，由有权管理员手动触发，查询统一账户中心的权威状态。本轮不实现企微事件驱动、定时调度、自动重试调度或专用同步管理页面；既有自动入口不得绕过本轮手动执行策略。接口必须能返回或查询执行状态、处理范围、成功/失败及部分失败结果，具体契约留待规格确定。不能以企微缺失记录直接认定离职。全量同步必须取得完整分页快照并验证完整性，再产生差异并幂等执行；空快照、分页中断或部门失败不能引发批量误清权。

依照经确认的组织映射规则，为新员工、新部门供给身份、应有空间及 code 工作区关系；新员工在两端能够进入授权空间。调岗先计算差异，再增新收旧，新部门权限在两端可用，旧受管权限被回收。重复同步不得重复创建身份、空间/工作区关系或扩大授权；新增授权步骤失败必须可观察并能安全重试。

调岗、主管降权、离职和停用须回收由组织管理的旧权限、会话和运行授权，保留有来源依据的手工授权。同步执行、失败步骤和人工重试可追溯，重复或并发手动触发不得相互覆盖或扩大授权；失败须通过接口结果与运行记录对管理员可见，不新增独立告警平台。历史映射规则变更先明确旧行为、预演影响再迁移。

达成依据：ACC-006。对应 v3 §5。

### REQ-007 企业技能发布与安全分发

企业技能分发是本轮必做能力，不以后续阶段替代验收。knowledge-opc catalog 是企业技能管理源。保留母空间广播能力，但技能按独立发布任务管理源、目标空间、版本、哈希、幂等映射和下架策略，不默认向所有沙箱安装全部技能。

两端只安装经授权、指定不可变版本且可完整校验的技能包。内容哈希以实际字节为准；包的执行模式、适用客户端、工具类别声明必须可验证。未声明或验证失败的包默认不进入本地执行。防止路径越界、符号链接逃逸、大小/文件数超限、版本替换和半安装状态；账号与空间的受管缓存相互隔离，个人同名技能不得静默遮蔽企业技能。

完整归档获取先验证现有接口；再评估受限只读归档适配或必要的 knowledge-opc 接口扩展。不得用预览文本拼成残缺包，也不得靠管理员 token 绕过员工权限。下载后本地执行的可撤销授权、缓存失效和离线边界须在规格中明确。

达成依据：ACC-007。对应 v3 §4.3、§5、§6、§8。

### REQ-008 云端 Agent 委托（本轮移出，编号保留）

用户于 2026-10-20 明确选择“本轮不做，记入待办”。云端 Agent 任务、完整会话状态恢复及其委托流程不进入本轮交付或验收，记录于主仓 [backlog](../../../../backlog.md)。不影响 REQ-009 精确 MCP 调用自身所需的授权、OAuth、审批、取消与未知结果处理。

### REQ-009 精确调用企业 MCP 工具

精确调用企业 MCP 是本轮必做能力。两端可在当前员工、空间和运行授权下调用明确的企业 MCP 工具；工具可见性和凭据使用遵循 REQ-002、REQ-003，不依赖 REQ-008 的云端 Agent 委托。云 stdio 工具仍在服务器执行，不把命令和环境变量分发到本机。

工具需要个人 OAuth 或人工审批时，使用当前员工的授权上下文。个人 OAuth 凭据只能在其所属用户、允许空间、目标服务和有效授权范围内使用；可在该许可范围内用于多次调用，每次调用仍检查当前授权和撤销状态，不因正常重复调用要求员工重新授权。工具审批绑定具体请求及获批操作，不得挪用于其他请求；有权交互用户才能审批，执行 token 不能自审批，过期或重复审批不能扩大权限。同一请求的幂等查询或重复回调不得造成重复副作用。呈现执行中、等待授权/审批、成功、失败、取消和结果未知等实际调用状态，并能在连接中断后查询调用结果；不据此新增通用 Agent 会话恢复系统。取消不伪称回滚已发生的副作用，写调用超时不自动重试；无法确认结果时保留可追踪的请求身份并显示结果未知。端点级 `ask` 的共享机器主体不能冒充个人工具执行。

必须单独验证精确调用链路，不能以 `ask` 问答成功充当该能力验收。网关不复制 OPC 凭据解密与 OAuth 刷新机制。现有接口不足时先说明必要扩展与升级维护影响，取得用户确认后再改变 knowledge-opc。

达成依据：ACC-008、ACC-009。对应 v3 §4.4、§8。

### REQ-010 双客户端受管执行与兼容性

保留 work 本地执行引擎、办公会话和审批能力；保留 code 自有后端/数据库、任务/Git 和 Daemon。企业能力遵守各仓既有边界，不通过替换整套执行引擎完成集成。

code 企业 MCP 配置获取或解析失败时必须失败关闭，不能落回继承本机全部 MCP 的状态；受管空配置和继承本机配置含义不同。Claude Code、Codex、Kimi Code 分别验证真实执行参数与权限行为，不默认放开本机高权限模式，不将云审批等同于 CLI 权限模式。

macOS 上企业长期凭据进入系统安全存储，不写普通配置 JSON、会话日志或工具参数。两端升级兼容与旧客户端错误行为须可验证。

达成依据：ACC-001、ACC-003、ACC-009。对应 v3 §6。

### REQ-011 兼容升级、灰度和回滚

企业资源继续由 knowledge-opc 管理，新增集成的部署配置与上游部署物保持可维护边界。记录源码 SHA、补丁、镜像 digest、配置/迁移版本和契约测试集，不能以源码 HEAD 相同代替镜像来源证明。

本轮按固定版本实施最小必要发布与回滚方案，不新建通用发布平台、跨版本自动升级矩阵或全流程发布自动化。发布先经过测试镜像、两类角色/两空间必要契约测试、单部门灰度，再扩大；涉及存量数据兼容或迁移时使用具有代表性存量数据的副本验证。兼容检查失败必须阻断相关写入，不能仅报警或回退到高权限访问。每个发布步骤具有验证、回滚触发条件和顺序；数据库变化必须验证迁移和回滚。

达成依据：ACC-010、ACC-011。对应 v3 §7、§9、§10。

### REQ-012 本轮必做目标与技术验证关口

验证 A：个人身份与撤权穿透两端及在途任务，是首个业务版本前置。验证 B：按权限完整获取技能包，是本地技能分发前置。验证 C 随 REQ-008 移出本轮，不阻塞本轮交付。精确 MCP 必须有独立的工具执行及个人授权、所需 OAuth/审批、取消和未知结果证据，不得借验证 C 后置而免除这些检查。

技术验证失败时，未验证能力保持关闭以保护试点，但该条需求仍未完成。必须修订方案、补充证据或请用户明确变更范围，不能将关闭能力、仅完成云问答或仅生成文档记为本轮完整交付。knowledge-opc 源码必要修改单独报批，不能因已建分支就认为获得修改授权。

达成依据：ACC-012。对应 v3 §8–11，用户后续明确决定优先于 v3 中允许后置的建议。

## 7. 非目标

### NG-001 不扩展首批客户端平台矩阵

本轮首批只验收 macOS、Claude Code/Codex/Kimi Code，不包含 Windows/Linux 客户端或其他 CLI；这是用户明确的首批范围，不排除后续产品扩展。

### NG-002 不建设第二套企业资源管理源

不复制知识向量库，不在网关另建独立维护知识、技能、MCP 和空间权限的后台，避免权威来源分裂。

### NG-003 不重写执行引擎或绕开本机许可

不替换两端引擎、任务/Git 或办公会话，不让云角色自动赋予本机文件/shell 权限。

### NG-004 不默认批准 knowledge-opc 源码扩展

默认复用现有能力；必要源码变更需单独说明和批准，避免升级维护范围失控。此限制不构成功能减免，参见 REQ-012。

### NG-005 不将内部试点等同于外部商业化上线

本轮不因未来对外方向而自动增加计费、合同、客户自助开户等独立产品范围；内部试点成果不能直接标记为外部商业化已完成。未来客户隔离约束需在架构设计中保留，不据此扩展本轮业务场景。

### NG-006 不承诺删除已返回信息或自动执行发布

撤权约束未来访问，不宣称远程删除员工已取得的信息。文档/分支授权不代表提交、推送、部署、数据库实际迁移或合并授权；这些动作按对应阶段明确授权执行。

### NG-007 本轮不做云端 Agent 委托及组织自动调度

REQ-008 及验证 C 移入后续待办；组织同步仅由受保护接口手动触发，不新增事件驱动、定时与自动重试调度或专用管理页面。MCP 调用所需的授权和审批仍属本轮。OpenBao 引入须另获明确批准；通用发布平台不属本轮。
